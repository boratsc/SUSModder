# SUSModder 3.0 Stable — E2E Release Gate Plan

**Data:** 2026-06-28  
**Zakres:** Steam/Epic, API v2, pobieranie modów, rozpakowanie, struktura plików, uruchamianie Among Us, logi BepInEx/Legendary  
**Status:** Plan do odhaczania przed wydaniem stabilnej wersji 3.0

---

## 1. Goal

Zweryfikować przed wydaniem 3.0 stable, że dla produkcyjnego API v2:

- katalog modów pobiera się poprawnie,
- każdy mod ma poprawne warianty downloadu,
- każdy deklarowany wariant Steam/Epic faktycznie pobiera plik,
- pobrane pliki mają poprawny SHA256,
- archiwa dają się rozpakować,
- struktura plików po instalacji jest zgodna z oczekiwaniami,
- pełne mody uruchamiają Among Us,
- BepInEx generuje świeże logi po starcie,
- logi nie zawierają krytycznych błędów ładowania pluginów,
- Steam i Epic flow działają end-to-end na realnym środowisku Windows.

## 2. Non-goals

- Nie testujemy multiplayer matchmakingu jako warunku wydania.
- Nie testujemy gameplayu każdej roli.
- Nie próbujemy automatycznie obchodzić Steam Guard/Epic OAuth.
- Nie robimy destrukcyjnych testów na głównej instalacji użytkownika bez izolowanego katalogu testowego.
- Nie uznajemy samego `HTTP 200` za wystarczający dowód instalacji.

## 3. Release gate checklist

### 3.1 Środowisko testowe Windows

- [ ] Windows 10/11 x64.
- [ ] Steam z zainstalowanym Among Us.
- [ ] Epic Games / Legendary zalogowany i gotowy do użycia.
- [ ] Konto Steam ma Among Us.
- [ ] Konto Epic ma Among Us.
- [ ] Minimum 30–50 GB wolnego miejsca.
- [ ] Ustalony izolowany katalog testowy, np. `%TEMP%\SUSModder-E2E-3.0\`.
- [ ] Logi i artefakty zapisywane do `TestResults/SUSModder-E2E/<timestamp>/`.

### 3.2 Izolacja danych

- [ ] Testy nie piszą do normalnego katalogu modów użytkownika, chyba że uruchomiono tryb manualny.
- [ ] Testy używają osobnego `ModsInstallPath`.
- [ ] Testy używają osobnej testowej bazy SQLite albo izolowanego profilu.
- [ ] Testy zapisują pełny raport JSON/Markdown.
- [ ] Testy mają tryb `--no-cleanup` do zostawienia uszkodzonej instalacji po FAIL.
- [ ] Testy mają tryb `--cleanup` do usuwania artefaktów po PASS.

## 4. API v2 catalog/download gate

Bazowe istniejące skrypty:

- `SKRYPTY/Test/test-api-e2e.ps1`
- `SKRYPTY/Test/test-api-v2-client.ps1`
- `SKRYPTY/Test/test-downloads.py`

Wymagane rozszerzenie: obecne smoke testy muszą zostać rozszerzone z `HEAD/HTTP` do pełnego downloadu, SHA256, extract i structure verification.

### 4.1 Catalog smoke

- [ ] `GET /catalog?limit=50` zwraca 200.
- [ ] Liczba modów > 0.
- [ ] Każdy mod ma `id`, `name`, `modType`, `currentVersion`.
- [ ] Każdy mod ma `iconUrl` albo jawnie uzasadniony brak.
- [ ] `GET /catalog/:id` działa dla każdego moda.
- [ ] Każdy `full` mod ma co najmniej jeden wariant platformowy.
- [ ] Każdy `dll` mod ma co najmniej jeden wariant downloadu.
- [ ] `GET /catalog/:id/versions` działa dla każdego moda.
- [ ] `GET /compatibility/snapshot` działa i nie zwraca pustej matrycy.
- [ ] `GET /versions` działa.
- [ ] `GET /versions/:dbValue` działa dla wersji używanych przez obecne mody.

### 4.2 Download redirect / metadata

Dla każdego moda i każdego wariantu z `/catalog/:id`:

- [ ] `GET /downloads/mod/:id/:version?platform=<platform>&arch=<arch>` zwraca redirect/200.
- [ ] Finalny CDN URL zwraca 200.
- [ ] Nagłówek `X-SUSModder-SHA256` istnieje, jeśli backend go deklaruje.
- [ ] Nagłówek `X-SUSModder-File-Size` istnieje, jeśli backend go deklaruje.
- [ ] Rozmiar pliku > 0.
- [ ] Pobrany plik nie jest HTML-em błędu CDN.
- [ ] SHA256 finalnie pobranego pliku zgadza się z API.

## 5. Download + extraction gate

### 5.1 Full mod — Steam

Dla każdego full moda z wariantem Steam:

- [ ] Pobierz wariant `platform=steam`.
- [ ] Zweryfikuj SHA256.
- [ ] Rozpakuj do katalogu temp.
- [ ] Sprawdź, że archiwum nie zawiera path traversal ani ścieżek absolutnych.
- [ ] Zainstaluj przez istniejący core flow (`PlatformFullModInstanceInstaller` / `ModInstanceInstaller`).
- [ ] Sprawdź finalną strukturę:
  - [ ] `Among Us.exe` istnieje.
  - [ ] `BepInEx/` istnieje.
  - [ ] `BepInEx/plugins/` istnieje.
  - [ ] Co najmniej jeden oczekiwany plugin/mod DLL istnieje w `BepInEx/plugins/`, jeśli mod tego wymaga.

### 5.2 Full mod — Epic

Dla każdego full moda z wariantem Epic:

- [ ] Pobierz wariant `platform=epic`.
- [ ] Zweryfikuj SHA256.
- [ ] Rozpakuj do katalogu temp.
- [ ] Sprawdź, że archiwum nie zawiera path traversal ani ścieżek absolutnych.
- [ ] Zainstaluj przez `EpicFullModInstanceInstaller` / `EpicModInstaller`.
- [ ] Sprawdź finalną strukturę:
  - [ ] `targetInstallPath/AmongUs/Among Us.exe` albo inna jawnie oczekiwana struktura.
  - [ ] `targetInstallPath/AmongUs/BepInEx/`.
  - [ ] `targetInstallPath/AmongUs/BepInEx/plugins/`.

### 5.3 DLL mods

Dla każdego `dll` moda:

- [ ] Pobierz wariant Steam.
- [ ] Pobierz wariant Epic, jeśli istnieje.
- [ ] Zweryfikuj SHA256.
- [ ] Sprawdź nazwę DLL z `ModDownloadUrlBuilder.GetDllFileName`.
- [ ] Zainstaluj DLL do każdej kompatybilnej pełnej instancji.
- [ ] Sprawdź, że DLL trafił do `BepInEx/plugins`.
- [ ] Sprawdź installation map / metadata, jeśli dotyczy.
- [ ] Uruchom przynajmniej jedną pełną instancję z doinstalowanym DLL.

## 6. Launch gate — Steam

Dla każdego full moda Steam:

- [ ] Instalacja zakończyła się sukcesem.
- [ ] `Among Us.exe` istnieje.
- [ ] `steam_appid.txt` zostaje utworzony z `945360`.
- [ ] Start odbywa się przez `SteamLaunchSupervisor`.
- [ ] Proces `Among Us.exe` wystartował.
- [ ] Proces nie zakończył się przedwcześnie w oknie obserwacji 35–60 sekund.
- [ ] Po starcie pojawił się świeży `BepInEx/LogOutput.log`.
- [ ] `BepInExLogAnalyzer` nie wykrywa krytycznych błędów:
  - [ ] `FileNotFoundException`
  - [ ] `DllNotFoundException`
  - [ ] `BadImageFormatException`
  - [ ] `MissingMethodException`
  - [ ] `TypeLoadException`
  - [ ] `UnauthorizedAccessException`
- [ ] Snapshot pluginów zawiera oczekiwane DLL.
- [ ] Po teście proces zostaje zamknięty kontrolowanie.
- [ ] Raport zawiera PASS/FAIL oraz ścieżki logów.

---

## 7. Launch gate — Epic

Dla każdego full moda Epic:

- [ ] Instalacja zakończyła się sukcesem.
- [ ] Struktura `AmongUs/` jest poprawna.
- [ ] Legendary/Epic flow nie zwraca błędu.
- [ ] Start odbywa się przez istniejący `EpicVersionManager.HandleEpicGameAsync` albo dedykowany testowy wrapper.
- [ ] `legendary.log.txt` powstaje / jest aktualizowany.
- [ ] Nie występuje event `EpicLaunchError`.
- [ ] Proces gry wystartował albo Legendary potwierdziło launch w logu.
- [ ] Pojawił się świeży `BepInEx/LogOutput.log`.
- [ ] `BepInExLogAnalyzer` nie wykrywa krytycznych błędów.
- [ ] Proces zostaje zamknięty kontrolowanie.
- [ ] Raport zawiera PASS/FAIL + log Legendary + BepInEx.

## 8. Proponowany harness automatyzacji

### 8.1 Nowy runner

Proponowany skrypt:

```powershell
.\SKRYPTY\Test\run-release-e2e.ps1 `
  -ApiBase "https://api.susmodder-cdn.ovh/v2" `
  -Platforms steam,epic `
  -InstallRoot "$env:TEMP\SUSModder-E2E-3.0" `
  -Launch `
  -ObservationSeconds 45 `
  -NoCleanupOnFailure
```

Docelowo można dodać osobny projekt testowy:

- `SUSModder.E2E.Tests`

### 8.2 Tryby runnera

- [ ] `--api-only` — szybki gate backend/CDN.
- [ ] `--download-only` — pobiera wszystkie warianty i sprawdza SHA256.
- [ ] `--extract-only` — pobiera + rozpakowuje + sprawdza strukturę.
- [ ] `--install-only` — pełna instalacja bez launchu.
- [ ] `--launch-steam` — tylko Steam launch.
- [ ] `--launch-epic` — tylko Epic launch.
- [ ] `--full-release-gate` — wszystko.
- [ ] `--mod-id <id>` — pojedynczy mod do debugowania.
- [ ] `--keep-artifacts` — zostawia pliki.
- [ ] `--cleanup` — usuwa po PASS.

### 8.3 Artefakty

Każdy run zapisuje:

- [ ] `summary.md`
- [ ] `results.json`
- [ ] `catalog.snapshot.json`
- [ ] `downloads/*.headers.json`
- [ ] `downloads/*.sha256.txt`
- [ ] `install-logs/*.log`
- [ ] `launch-logs/<platform>/<mod>/LogOutput.log`
- [ ] `launch-logs/<platform>/<mod>/ErrorLog.log`
- [ ] `legendary.log.txt`, jeśli Epic
- [ ] `trx` z `dotnet test --logger trx`, jeśli runner jest projektem testowym

## 9. Kryteria PASS/FAIL dla stable 3.0

### 9.1 Blocker — nie wydajemy stable

- [ ] Jakikolwiek **full** mod z katalogu nie ma działającego downloadu dla deklarowanego wariantu.
- [ ] Jakikolwiek download ma SHA256 mismatch.
- [ ] Jakikolwiek full mod nie daje się rozpakować.
- [ ] Jakikolwiek full mod po instalacji nie ma poprawnej struktury BepInEx.
- [ ] Steam launch nie działa dla któregokolwiek full moda Steam.
- [ ] Epic launch nie działa dla któregokolwiek full moda Epic.
- [ ] Świeży BepInEx log nie pojawia się po starcie.
- [ ] BepInEx log zawiera krytyczne błędy plugin load.
- [ ] Test uszkadza normalną instalację użytkownika.
- [ ] API v2 catalog/download zwraca niespójne warianty.
- [ ] **DLL mod** nie ma żadnego działającego wariantu (cross-platform fallback nie zadziałał).

### 9.2 Warn — można świadomie zaakceptować

- [ ] Mod startuje, ale ma niekrytyczne warningi Unity/BepInEx.
- [ ] Download jest wolny, ale stabilny.
- [ ] Epic wymaga ponownego logowania.
- [ ] AV/SmartScreen ostrzega przy unsigned buildzie.
- [ ] Jeden wariant platformowy nie istnieje, ale API go nie deklaruje i UI poprawnie pokazuje brak dostępności.
- [ ] **DLL mod**: SHA256 mismatch na jednym wariancie, ale drugi wariant działa (cross-platform fallback w `SelectVariant`).

## 11. User workflow

### Dla release managera

1. Zbuduj build kandydujący do stable.
2. Uruchom `api-only` gate.
3. Uruchom `download-only` gate.
4. Uruchom `extract/install` gate.
5. Uruchom Steam launch gate.
6. Uruchom Epic launch gate.
7. Otwórz `summary.md` i `results.json`.
8. Jeśli są blockery — nie publikuj stable.
9. Jeśli są tylko warny — podejmij świadomą decyzję i wpisz do release notes.

### Dla debugowania jednego moda

1. Uruchom runner z `--mod-id <id>`.
2. Zostaw artefakty przez `--keep-artifacts`.
3. Sprawdź download headers, SHA256, strukturę instalacji i log BepInEx.
4. Popraw backend/CDN/metadane/mod package.
5. Powtórz test dla konkretnego moda.

## 12. Core business logic responsibilities

Core powinien odpowiadać za:

- [ ] Pobranie katalogu przez `SUSModderApiClient`.
- [ ] Enumerację modów i wariantów.
- [ ] Budowanie download URL przez `ModDownloadUrlBuilder`.
- [ ] Pobranie plików.
- [ ] SHA256 verification przez `Sha256Verifier`.
- [ ] Bezpieczne rozpakowanie.
- [ ] Instalację Steam/Epic przez istniejące installery.
- [ ] Snapshot finalnej struktury.
- [ ] Launch observation przez `SteamLaunchSupervisor` / Epic wrapper.
- [ ] Analizę logów przez `BepInExLogAnalyzer`.
- [ ] Raport JSON z maszynowo czytelnymi kodami błędów.

## 14. Config and migration implications

- [ ] Nie pisać runtime do `appsettings.json`.
- [ ] Testy ustawiają `ModsInstallPath` izolowanie.
- [ ] SQLite test DB osobno od użytkownika.
- [ ] Nie używać produkcyjnego `%APPDATA%/SUSModder/susmodder.db`, chyba że tryb manualny.
- [ ] `ConfigManager` / repozytoria muszą działać na testowym DB.
- [ ] Installation map można sprawdzać, ale nie może nadpisywać realnych danych użytkownika.

---

## 15. Platform, packaging, updater, telemetry, privacy, AV constraints

- [ ] Release gate uruchomić na buildzie zbliżonym do Velopack release.
- [ ] Osobno smoke: `GET /releases?channel=release` i `GET /releases?channel=beta`.
- [ ] Unsigned build: akceptujemy możliwy SmartScreen/AV warn, ale raportujemy.
- [ ] Testy nie wysyłają prywatnych ścieżek/kont do backendu.
- [ ] Logi redagują tokeny, authorization code, bearer tokeny i user-specific secrets.
- [ ] Epic/Steam credentials nigdy nie są zapisywane w raporcie.
- [ ] Telemetry w testach domyślnie off albo z jawnym `test` markerem, jeśli kiedyś będzie potrzebna.

## 17. Suggested implementation order

### P0 — przed stable

#### Ścieżka A — API/CDN/download

- [ ] Rozszerzyć `test-api-v2-client.ps1`, żeby iterował po wszystkich wariantach, nie tylko Steam x86.
- [ ] Dodać pełne pobieranie i SHA256 dla każdego wariantu.
- [ ] Dodać raport JSON/Markdown.
- [ ] Uruchomić na produkcji.

#### Ścieżka B — extraction/structure

- [ ] Dodać testowy runner instalacji do izolowanego folderu.
- [ ] Dla każdego full moda sprawdzić strukturę po instalacji.
- [ ] Dla każdego DLL moda sprawdzić instalację do kompatybilnych full modów.

#### Ścieżka C — launch

- [ ] Steam: użyć `SteamLaunchSupervisor` dla każdej instancji.
- [ ] Epic: opakować `EpicVersionManager` w testowy runner.
- [ ] Po starcie zebrać `BepInEx/LogOutput.log`.
- [ ] Użyć `BepInExLogAnalyzer`.
- [ ] Zapisać artefakty.

### P1 — po pierwszym gate

- [ ] Dodać `SUSModder.E2E.Tests` jako osobny projekt.
- [ ] Dodać kategorie testów: `Api`, `Download`, `Install`, `Launch`, `Steam`, `Epic`, `Slow`, `ManualCredentials`.
- [ ] Dodać `.runsettings` albo parametry środowiskowe dla ścieżek testowych.
- [ ] Dodać TRX output.
- [ ] Dodać `--mod-id` do debugowania jednego moda.

### P2 — po stable / hardening

- [ ] Automatyczny nightly API/download gate.
- [ ] Weekly pełny download/extract gate.
- [ ] Manualny launch gate przed każdą wersją stable.
- [ ] Dashboard trendów: który mod pada, kiedy, na jakiej platformie.
