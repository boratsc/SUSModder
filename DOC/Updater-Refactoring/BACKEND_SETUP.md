## 1. Requirements

### 1.1. Minimalne Wymagania

- **Web server:** NGINX 1.18+, Apache 2.4+, lub CDN (CloudFlare, AWS CloudFront)
- **HTTPS:** Required (Velopack wymaga HTTPS dla security)
- **Storage:** ~500MB na wersję (full .nupkg ~50MB, delta ~5-15MB)
- **Bandwidth:** ~10GB/miesiąc dla 1000 active users (z deltami)

### 1.2. Recommended Setup

```
Option A: VPS/Dedicated Server
├─ NGINX as reverse proxy
├─ Static file serving (/releases/)
└─ HTTPS via Let's Encrypt

Option B: CDN/Static Hosting
├─ AWS S3 + CloudFront
├─ Or: CloudFlare Pages
└─ Or: Azure Blob Storage + CDN

Option C: Hybrid (Recommended)
├─ Main API on VPS
├─ /releases/ on CDN (static files)
└─ Best performance + low cost
```

## 2. Directory Structure

### 2.1. Server File Layout

```
/var/www/susmodder/
├─ releases/                                (Public - Velopack updates)
│   ├─ releases.win.json                    (JSON manifest - channel: win)
│   ├─ SUSModder-2.0.1-win-full.nupkg       (Initial version)
│   ├─ SUSModder-2.1.0-win-full.nupkg       (New full)
│   ├─ SUSModder-2.1.0-win-delta.nupkg      (Delta from 2.0.1)
│   ├─ SUSModder-2.1.1-win-delta.nupkg      (Delta from 2.1.0)
│   └─ SUSModderSetup.exe                   (Installer dla fresh installs)
│
├─ updates/                                 (Legacy - dla v2.0.1 users)
│   └─ SUSModder-2.0.2.zip                  (Bridge update)
│
└─ api/                                     (Backend API)
    └─ (Your existing Node.js/Python API)
```

> **Note:** Endpoint `GET /api/releases` (opis w sekcji 8) pełni rolę warstwy serwisowej nad katalogiem `releases/`. Backend odczytuje manifest `releases.{channel}.json` i udostępnia go jako JSON API wraz z dodatkowymi metadanymi, kontrolą błędów i nagłówkami HTTP.

## 3. NGINX Configuration

### 3.1. Basic Configuration

**File:** `/etc/nginx/sites-available/susmodder.app`

```nginx
server {
    listen 443 ssl http2;
    server_name susmodder.app;

    # SSL Configuration (Let's Encrypt)
    ssl_certificate /etc/letsencrypt/live/susmodder.app/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/susmodder.app/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_prefer_server_ciphers on;

    # Root directory
    root /var/www/susmodder;

    # ═══════════════════════════════════════════════════════════
    # Velopack Updates - Static file serving
    # ═══════════════════════════════════════════════════════════
    location /releases/ {
        alias /var/www/susmodder/releases/;

        # Disable directory listing
        autoindex off;

        # CORS headers (if needed for web-based updater)
        add_header Access-Control-Allow-Origin *;
        add_header Access-Control-Allow-Methods "GET, HEAD";

        # JSON manifests (releases.{channel}.json)
        location ~ /releases/releases\.[a-z]+\.json$ {
            default_type application/json;
            add_header Content-Type "application/json; charset=utf-8";
            add_header Cache-Control "max-age=300"; # 5 minutes
        }

        # .nupkg files as application/octet-stream
        location ~ \.nupkg$ {
            default_type application/octet-stream;
            add_header Content-Disposition "attachment";
            add_header Cache-Control "public, max-age=31536000, immutable"; # 1 year
        }

        # Setup.exe
        location ~ /releases/.*Setup\.exe$ {
            default_type application/octet-stream;
            add_header Content-Disposition "attachment; filename=SUSModderSetup.exe";
            add_header Cache-Control "max-age=3600"; # 1 hour
        }
    }

    # ═══════════════════════════════════════════════════════════
    # Legacy Updates (dla v2.0.1 users)
    # ═══════════════════════════════════════════════════════════
    location /api/download-latest {
        alias /var/www/susmodder/updates/SUSModder-2.0.2.zip;
        default_type application/zip;
        add_header Content-Disposition "attachment; filename=SUSModder-Update.zip";
        add_header Cache-Control "max-age=3600";
    }

    # ═══════════════════════════════════════════════════════════
    # API Proxy (Your existing backend)
    # ═══════════════════════════════════════════════════════════
    location /api/ {
        proxy_pass http://localhost:3001;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # ═══════════════════════════════════════════════════════════
    # Logging
    # ═══════════════════════════════════════════════════════════
    access_log /var/log/nginx/susmodder-access.log;
    error_log /var/log/nginx/susmodder-error.log;

    # ═══════════════════════════════════════════════════════════
    # Security Headers
    # ═══════════════════════════════════════════════════════════
    add_header X-Content-Type-Options nosniff;
    add_header X-Frame-Options DENY;
    add_header X-XSS-Protection "1; mode=block";
}

# HTTP → HTTPS redirect
server {
    listen 80;
    server_name susmodder.app;
    return 301 https://$server_name$request_uri;
}
```

## 4. Apache Configuration

### 4.1. Basic Configuration

**File:** `/etc/apache2/sites-available/susmodder.app.conf`

```apache
<VirtualHost *:443>
    ServerName susmodder.app
    DocumentRoot /var/www/susmodder

    # SSL Configuration
    SSLEngine on
    SSLCertificateFile /etc/letsencrypt/live/susmodder.app/fullchain.pem
    SSLCertificateKeyFile /etc/letsencrypt/live/susmodder.app/privkey.pem
    Include /etc/letsencrypt/options-ssl-apache.conf

    # ══════════════════════════════════════════════════════
    # Velopack Updates
    # ══════════════════════════════════════════════════════
    <Directory "/var/www/susmodder/releases">
        Options -Indexes +FollowSymLinks
        AllowOverride None
        Require all granted

        # JSON manifests (releases.{channel}.json)
        <FilesMatch "^releases\.[a-z]+\.json$">
            ForceType application/json
            Header set Content-Type "application/json; charset=utf-8"
            Header set Cache-Control "max-age=300"
        </FilesMatch>

        # .nupkg files
        <FilesMatch "\.nupkg$">
            ForceType application/octet-stream
            Header set Content-Disposition "attachment"
            Header set Cache-Control "public, max-age=31536000, immutable"
        </FilesMatch>

        # Setup.exe
        <FilesMatch "Setup\.exe$">
            ForceType application/octet-stream
            Header set Content-Disposition "attachment; filename=SUSModderSetup.exe"
            Header set Cache-Control "max-age=3600"
        </FilesMatch>
    </Directory>

    # ══════════════════════════════════════════════════════
    # Legacy Update Endpoint
    # ══════════════════════════════════════════════════════
    Alias /api/download-latest /var/www/susmodder/updates/SUSModder-2.0.2.zip

    # ══════════════════════════════════════════════════════
    # API Proxy
    # ══════════════════════════════════════════════════════
    ProxyPreserveHost On
    ProxyPass /api/ http://localhost:3001/api/
    ProxyPassReverse /api/ http://localhost:3001/api/

    # Logging
    ErrorLog ${APACHE_LOG_DIR}/susmodder-error.log
    CustomLog ${APACHE_LOG_DIR}/susmodder-access.log combined

    # Security Headers
    Header always set X-Content-Type-Options nosniff
    Header always set X-Frame-Options DENY
    Header always set X-XSS-Protection "1; mode=block"
</VirtualHost>

# HTTP → HTTPS redirect
<VirtualHost *:80>
    ServerName susmodder.app
    Redirect permanent / https://susmodder.app/
</VirtualHost>
```

## 5. Static Hosting (S3/CDN)

### 5.1. AWS S3 + CloudFront

**Setup:**

```bash
# 1. Create S3 bucket
aws s3 mb s3://susmodder-releases --region us-east-1

# 2. Enable static website hosting
aws s3 website s3://susmodder-releases --index-document index.html

# 3. Set bucket policy (public read)
cat > bucket-policy.json <<EOF
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadGetObject",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::susmodder-releases/*"
    }
  ]
}
EOF

aws s3api put-bucket-policy --bucket susmodder-releases --policy file://bucket-policy.json

# 4. Upload releases
aws s3 sync ./releases/ s3://susmodder-releases/ \
    --acl public-read \
    --exclude "*" \
    --include "*.nupkg" \
    --include "releases.*.json" \
    --include "*.exe"

# 5. Set content types for JSON manifests
aws s3 cp s3://susmodder-releases/releases.win.json s3://susmodder-releases/releases.win.json \
    --content-type "application/json" \
    --metadata-directive REPLACE \
    --acl public-read

# 6. Create CloudFront distribution
aws cloudfront create-distribution --origin-domain-name susmodder-releases.s3.amazonaws.com
```

**Cost estimate (1000 active users):**
```
S3 Storage: 500MB × $0.023/GB = $0.01/month
S3 Requests: 10,000 GET × $0.0004/1000 = $0.004/month
CloudFront Transfer: 10GB × $0.085/GB = $0.85/month

TOTAL: ~$1/month
```

## 6. CI/CD Integration

### 6.1. GitHub Actions Workflow

**File:** `.github/workflows/release.yml`

```yaml
name: Build and Release

on:
  push:
    tags:
      - 'v*.*.*'

jobs:
  build-and-release:
    runs-on: windows-latest

    steps:
      - uses: actions/checkout@v3

      - name: Setup .NET
        uses: actions/setup-dotnet@v3
        with:
          dotnet-version: '8.0.x'

      - name: Install Velopack CLI
        run: dotnet tool install -g vpk

      - name: Extract version from tag
        id: get_version
        run: |
          $version = "${{ github.ref }}" -replace 'refs/tags/v', ''
          echo "VERSION=$version" >> $env:GITHUB_OUTPUT

      - name: Update version in files
        run: |
          $version = "${{ steps.get_version.outputs.VERSION }}"
          (Get-Content SUSModder/appsettings.json) -replace '"CurrentVersion": ".*"', "`"CurrentVersion`": `"$version`"" | Set-Content SUSModder/appsettings.json
          (Get-Content SUSModder/SUSModder.nuspec) -replace '<version>.*</version>', "<version>$version</version>" | Set-Content SUSModder/SUSModder.nuspec

      - name: Restore dependencies
        run: dotnet restore

      - name: Build
        run: dotnet build -c Release

      - name: Publish
        run: dotnet publish SUSModder/SUSModder.csproj -c Release -r win-x64 --self-contained -o ./publish/susmodder

      - name: Pack with Velopack
        run: |
          $version = "${{ steps.get_version.outputs.VERSION }}"
          vpk pack `
            --packId SUSModder `
            --packVersion $version `
            --packDir ./publish/susmodder `
            --mainExe SUSModder.exe `
            --outputDir ./releases `
            --channel win

      - name: Sign packages
        env:
          CERT_PASSWORD: ${{ secrets.CERT_PASSWORD }}
        run: |
          # Decode certificate from base64 secret
          $certBytes = [Convert]::FromBase64String("${{ secrets.CODE_SIGNING_CERT }}")
          [IO.File]::WriteAllBytes("cert.pfx", $certBytes)

          # Sign all .nupkg files
          Get-ChildItem ./releases/*.nupkg | ForEach-Object {
            signtool sign /f cert.pfx /p $env:CERT_PASSWORD /t http://timestamp.digicert.com $_.FullName
          }

          # Sign Setup.exe
          signtool sign /f cert.pfx /p $env:CERT_PASSWORD /t http://timestamp.digicert.com ./releases/*Setup.exe

          # Cleanup
          Remove-Item cert.pfx

      - name: Upload to S3
        env:
          AWS_ACCESS_KEY_ID: ${{ secrets.AWS_ACCESS_KEY_ID }}
          AWS_SECRET_ACCESS_KEY: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
        run: |
          aws s3 sync ./releases/ s3://susmodder-releases/ \
            --acl public-read \
            --exclude "*" \
            --include "*.nupkg" \
            --include "releases.*.json" \
            --include "*.exe"

      - name: Invalidate CloudFront cache
        env:
          AWS_ACCESS_KEY_ID: ${{ secrets.AWS_ACCESS_KEY_ID }}
          AWS_SECRET_ACCESS_KEY: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
        run: |
          aws cloudfront create-invalidation \
            --distribution-id ${{ secrets.CLOUDFRONT_DISTRIBUTION_ID }} \
            --paths "/releases.*.json" "/*Setup.exe"

      - name: Create GitHub Release
        uses: softprops/action-gh-release@v1
        with:
          files: |
            ./releases/*Setup.exe
            ./releases/*.nupkg
            ./releases/releases.*.json
          body: |
            ## SUSModder v${{ steps.get_version.outputs.VERSION }}

            **Instalacja:**
            - Fresh install: Download `SUSModderSetup.exe`
            - Update: Automatyczny przez aplikację (Velopack)

            **Zmiany:**
            (See CHANGELOG.md)
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

### 6.2. Manual Deployment Script

**File:** `deploy-release.ps1`

```powershell
param(
    [Parameter(Mandatory=$true)]
    [string]$Version,

    [Parameter(Mandatory=$false)]
    [string]$Server = "deploy@susmodder.app"
)

$ErrorActionPreference = "Stop"

Write-Host "Deploying SUSModder v$Version to $Server..." -ForegroundColor Cyan

# 1. Build release locally (see build-release-velopack.ps1 from CODE_EXAMPLES.md)
& ".\build-release-velopack.ps1" -Version $Version

# 2. Upload to server
Write-Host "Uploading to server..." -ForegroundColor Yellow
scp -r ./releases/* "$Server:/var/www/susmodder/releases/"

# 3. Set permissions on server
Write-Host "Setting permissions..." -ForegroundColor Yellow
ssh $Server "chmod 644 /var/www/susmodder/releases/* && chown www-data:www-data /var/www/susmodder/releases/*"

# 4. Verify JSON manifest
Write-Host "Verifying deployment..." -ForegroundColor Yellow
$manifestContent = Invoke-WebRequest -Uri "https://susmodder.app/releases/releases.win.json" -UseBasicParsing
$manifest = $manifestContent.Content | ConvertFrom-Json
if ($manifest.LatestVersion -eq $Version) {
    Write-Host "✓ Deployment successful! Version $Version is live." -ForegroundColor Green
} else {
    Write-Host "✗ Deployment verification failed!" -ForegroundColor Red
    exit 1
}

Write-Host "`nLatest manifest:" -ForegroundColor Cyan
Write-Host ($manifest | ConvertTo-Json -Depth 10)
```

### 7.3. Application Telemetry

**Track update success/failure:**

```csharp
// In VelopackUpdateService.cs
public async Task<UpdateDownloadResult> DownloadAndApplyUpdateAsync(...)
{
    var startTime = DateTime.UtcNow;

    try
    {
        await _updateManager.DownloadUpdatesAsync(updateInfo, progress);
        _updateManager.ApplyUpdatesAndRestart(updateInfo);

        // Track success
        _telemetryService.TrackEvent("update_success", new Dictionary<string, string>
        {
            {"from_version", _currentVersion},
            {"to_version", updateInfo.TargetFullRelease.Version.ToString()},
            {"duration_seconds", (DateTime.UtcNow - startTime).TotalSeconds.ToString()},
            {"package_type", "delta_or_full"} // Velopack auto-selects
        });

        return new UpdateDownloadResult { Success = true };
    }
    catch (Exception ex)
    {
        // Track failure
        _telemetryService.TrackEvent("update_failure", new Dictionary<string, string>
        {
            {"from_version", _currentVersion},
            {"error", ex.Message},
            {"duration_seconds", (DateTime.UtcNow - startTime).TotalSeconds.ToString()}
        });

        return new UpdateDownloadResult { Success = false, ErrorMessage = ex.Message };
    }
}
```

## 8. API Endpoint: /api/releases

### 8.1. Cel i Zakres

- Udostępnia zunifikowany manifest aktualizacji dla aplikacji desktopowej (Velopack) oraz paneli administracyjnych.
- Abstrahuje fizyczny storage (`/releases/`), umożliwiając dodanie logowania, rate limiting i przyszłe rozszerzenia bez zmian po stronie klientów.
- Umożliwia obsługę wielu kanałów dystrybucji (np. `win`, `win-beta`) przy pomocy parametrów zapytania.

### 8.2. Specyfikacja Zapytania

| Metoda | Ścieżka         | Parametry zapytania           | Wymagane | Opis                                                |
|--------|-----------------|-------------------------------|----------|-----------------------------------------------------|
| GET    | `/api/releases` | `channel` (string, domyślnie `win`) | Nie       | Zwraca manifest Velopack dla wybranego kanału.      |
|        |                 | `arch` (string, domyślnie `x64`)   | Nie       | Rezerwacja pod przyszłe rozszerzenia (ARM, x86).    |

Nagłówki klienta: `Accept: application/json` (opcjonalnie). Odpowiedź ustawia `Content-Type: application/json; charset=utf-8`.

### 8.3. Odpowiedź 200 OK (przykład)

```json
{
  "success": true,
  "channel": "win",
  "arch": "x64",
  "latestVersion": "2.1.0",
  "updatedAt": "2025-10-28T14:33:12.000Z",
  "downloadBaseUrl": "https://susmodder.app/releases",
  "manifest": {
    "LatestVersion": "2.1.0",
    "Releases": [
      {
        "Version": "2.1.0",
```

### 8.4. Kody odpowiedzi i błędów

| Kod | Sytuacja                                | Payload przykładowy                                                     |
|-----|-----------------------------------------|-------------------------------------------------------------------------|
| 200 | Manifest zwrócony poprawnie             | Zgodnie z przykładem powyżej                                            |
| 304 | Klient posiada aktualną wersję (ETag)   | Brak treści; nagłówki `ETag` i `Cache-Control` ustawione                |
| 400 | Nieobsługiwany kanał/architektura       | `{ "success": false, "error": "invalid_channel", "message": "..." }`        |
| 404 | Brak manifestu dla kanału               | `{ "success": false, "error": "manifest_not_found", "message": "..." }`    |
| 500 | Błąd odczytu pliku / nieoczekiwane      | `{ "success": false, "error": "manifest_read_error", "message": "..." }`  |

### 8.5. Szkic implementacji (Node.js / Express)

```javascript
router.get('/releases', async (req, res) => {
  const channel = sanitizeIdentifier((req.query.channel || DEFAULT_CHANNEL).toLowerCase(), 'channel');
  const arch = sanitizeIdentifier((req.query.arch || DEFAULT_ARCH).toLowerCase(), 'arch');

  if (!allowedChannels.includes(channel)) {
    return res.status(400).json({ success: false, error: 'invalid_channel', message: `Channel ${channel} is not supported.` });
  }

  const manifestDir = resolveReleasesDir();
  if (!manifestDir) {
    return res.status(500).json({ success: false, error: 'releases_directory_missing', message: 'Velopack releases directory is not configured.' });
  }

  const manifestPath = path.join(manifestDir, `releases.${channel}.json`);
  try {
    await fsp.access(manifestPath);
  } catch {
    return res.status(404).json({ success: false, error: 'manifest_not_found', message: `Manifest for channel ${channel} was not found.` });
  }

  const [raw, stats] = await Promise.all([
    fsp.readFile(manifestPath, 'utf-8'),
    fsp.stat(manifestPath)
  ]);

  const manifest = JSON.parse(raw);
  const etag = computeEtag(raw);

  if (req.headers['if-none-match'] === etag) {
    return res.status(304).set({ 'ETag': etag, 'Cache-Control': CACHE_CONTROL_HEADER }).end();
  }

  res.set({
    'Content-Type': 'application/json; charset=utf-8',
    'Cache-Control': CACHE_CONTROL_HEADER,
    'ETag': etag
  }).json({
    success: true,
    channel,
    arch,
    latestVersion: extractLatestVersion(manifest),
    updatedAt: stats.mtime.toISOString(),
    downloadBaseUrl: process.env.VELOPACK_DOWNLOAD_BASE_URL ?? manifest.downloadBaseUrl ?? manifest.downloadBaseURL,
    manifest
  });
});
```

Analogiczny wzorzec można zastosować w środowisku .NET (`Minimal API`), Python (`FastAPI`) czy PHP (`Laravel`). Kluczowe jest odczytanie i zwrócenie manifestu jako JSON plus kontrola błędów.

### 8.6. Walidacja, Bezpieczeństwo, Cache

- Walidacja parametrów wejściowych (allowlist kanałów, minimalne/ maksymalne długości).
- Opcjonalne limitowanie ruchu: np. `IP rate limit = 60 zapytań/min`.
- Domyślnie zwracane jest `Cache-Control: public, max-age=300, stale-while-revalidate=120` oraz nagłówek `ETag` umożliwiający odpowiedzi 304.
- Brak CORS (aplikacja desktopowa). Włączyć jedynie dla paneli webowych.
- Logować `channel`, `arch`, `user-agent`, `ip`, `responseStatus` dla metryk adopcji.
- Monitorować błędy w centralnym logowaniu (ELK, Loki) i alertować dla 5xx.

### 8.7. Integracja z CI/CD

1. Pipeline build (`build-release-velopack.ps1`) generuje paczki i manifest `releases.{channel}.json`.
2. Crojob/Action wysyła artefakty do `releases/` (SCP, rsync, S3 sync, itp.).
3. Po deployu pipeline wykonuje sanity-check: `curl -f https://susmodder.app/api/releases?channel=win`.
4. Optional: webhook do Discorda/Slacka z informacją `latestVersion` + link do release notes.
5. W przypadku środowisk staging/beta można korzystać z osobnej domeny (`staging.susmodder.app`) lub parametru `channel=win-beta`.

### 8.8. Zmienne środowiskowe i ścieżki

| Zmienna                          | Domyślna wartość                                              | Opis                                                                 |
|----------------------------------|----------------------------------------------------------------|----------------------------------------------------------------------|
| `VELOPACK_DEFAULT_CHANNEL`      | `win`                                                           | Kanał używany, gdy klient nie poda `channel`.                        |
| `VELOPACK_DEFAULT_ARCH`         | `x64`                                                           | Domyślna architektura w parametrach zapytania.                        |
| `VELOPACK_CHANNELS`             | `win`                                                           | Lista dozwolonych kanałów (CSV), np. `win,win-beta`.                  |
| `VELOPACK_ARCHES`               | `x64`                                                           | Lista dozwolonych architektur (CSV).                                  |
| `VELOPACK_RELEASES_DIR`         | auto-detekcja (`../versions`, `../nginx/html/...`)              | Wymuszenie konkretnego katalogu z manifestami.                        |
| `VELOPACK_DOWNLOAD_BASE_URL`    | `undefined` (przyjmuje wartość z manifestu)                     | Nadpisuje `downloadBaseUrl` w odpowiedzi API.                         |
| `VELOPACK_CACHE_CONTROL`        | `public, max-age=300, stale-while-revalidate=120`               | Wartość nagłówka `Cache-Control`.                                     |

> Ścieżka do katalogu releases jest wykrywana wg priorytetu: zmienna środowiskowa → `../versions` → katalogi montowane w kontenerach (`nginx/html/susmodder-velopack`, `nginx/html/susmodder-versions`). Pierwszy dostępny katalog jest zapamiętywany w pamięci procesu.

### 8.9. Przyszłe rozszerzenia

- Autoryzacja kanałów beta (`Authorization: Bearer <token>`).
- `/api/v1/releases` jako wersjonowanie gdy nastąpi breaking change.
- Endpoint POST z panelu administracyjnego do publikacji nowego manifestu (z podpisami SHA1/SHA256).
- Możliwość zwracania changelogów (pole `releaseNotesUrl`) oraz hashów SHA256.
